# Skill index

The skills this verdict can route to, and the axis each one closes. Everything listed here ships in this repo at the same level as `readiness/`.

| Skill | Closes |
|---|---|
| `triage/` | axes 2, 3, 4 — names the problem, the failure mode, the constraint; writes the brief |
| `grilling/` | axis 6 — decision rounds until no question is left open |
| `grill-with-docs/` | axis 6 plus ADRs and a glossary |
| `domain-modeling/` | axis 6 vocabulary, when the words themselves are the gap |
| `to-spec/` | axes 4 and 5, synthesised into one document |
| `to-tickets/` | axis 7 — slicing with explicit blockers |
| `wayfinder/` | axis 7 when the route is genuinely invisible |
| `implement/` | consumes tickets, writes the code |
| `implement-spec/` | implements against a spec instead of tickets |
| `diagnosing-bugs/` | axis 2 when the failure mode is unknown |
| `prototype/` | axis 7 when one experiment retires the uncertainty cheaper than a plan |
| `code-review/` | axis 8 — proof by review |
| `handoff/` | the PARK verdict: work blocked on a person or another session |
| `retro/` | axis 8 after the fact, for the next cycle |
| `writing-for-agents/` | any axis where the deliverable is prose an agent must execute |
| `codebase-design/` | axis 4 when the surface does not exist yet |
| `loopy/` | axis 7 for long autonomous runs |
| `fitness-audit/` | axis 1 and axis 3 when a component's fitness is the open question |

## What is not here

The original index also pointed at two further roots on one machine: a set of client-specific skills (a storefront's theme, publishing, CRO and ads workflows) and a third-party pack (`architect`, `arena`, an interrogation review pass, a TDD cycle skill, and the the third-party principle pack family).

Neither is published: the first is someone's private business, the second is someone else's work. Where a verdict needs one of them, read that as "a skill of this shape exists", not as a broken link.
